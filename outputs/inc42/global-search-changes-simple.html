Correction to the 10 Sep build order

It said step 1 (exact match pin) needs no index rebuild. That is only partly true. The service can pin an exact name only if the search already returned that record. Today CRED comes back 11th of 15 out of 175 matches; at 16th, the service would never see it.

Quick version: fetch a wider candidate set and pin in the service. Guaranteed version: needs the cleaned exact-name field, which comes with the reindex.

Unchanged from Ashish's PRD: search modal, Entity vs Analytical routing, Ask DataLabs, company quality formula, type weights, the original 5 level weights, per-type cap numbers, display cap of 10.

Part 3

Two additions to the Search scope of work

1. Make workflow failure: capture and retry

What
When the Make workflow fails, the failure is recorded and the run is retried automatically
Capture
Log every failed run: time, step that failed, error message, records affected
Retry
Retry automatically a fixed number of times, with a gap between attempts
If retries run out
Alert the owner. The failed run stays visible until someone fixes it
Done when
No failed run is silently skipped. Every failure is either retried successfully or alerted
Link to search
If this workflow is what syncs records into the search index, a failed run means missing records and stale quality scores. No ranking logic fixes that
To confirm
Which Make workflow(s) this covers, retry count and gap, who gets the alert

2. Logic changes and workflow enhancements

What
Build the 14-step chain in Part 1 into search
Build order
  1. Exact match at rank 1 (quick version in the service; guaranteed after reindex), and treat spacing and punctuation the same
  2. Fix records that show on inc42.com search but return nothing on DataLabs (matter, byjus, of business)
  3. Score all types together
  4. Whole-word match, all-words-first, sounds-like guard, suffix stripping
  5. Alias table, investor quality, duplicate removal
  6. Typing wait, ignore late responses, separate error state
Done when
All test queries return the right answer at rank 1 (full list in the 10 Sep document, section 18)
Rule
Do not move other surfaces onto the DataLabs search endpoint until this passes. inc42.com search already shows CRED, Ola and Navi first
Out of scope

Not fixed by these changes

IssueWhy
Article search on inc42.comSeparate workstream
Companies missing from the database (Wagh Bakri, Lava, TBO Tek, BirdEye)No ranking rule finds a missing record. Data backlog
Search speed (target 200 ms, today ~1.8 s)Stated as a target, not solved by ranking rules
