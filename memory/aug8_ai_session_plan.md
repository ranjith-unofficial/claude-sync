Teaching spine: "An LLM predicts text, it does not look things up" — that one fact explains prompt failure, hallucination, and why agents need tools. Four beats: it's a predictor → prompt it like one → give it real information (grounding) → give it real abilities (agent).

**The agent to build = "Unit Companion"** — runs on the student's own real unit notes PDF. Answers from notes w/ section citation; falls back to web search when notes don't cover it (this decision branch IS the agent moment); generates + grades a 5-question quiz; logs weak topics to Google Sheets. Chosen over resume/placement agent, code-debugging agent, and attendance agent (reasons documented in artifact §4).

Deliberately NOT teaching: transformer internals, AI history/taxonomy, fine-tuning (90-sec aside only), model comparison tables, standalone ethics lecture, vector DB depth.

**Demo fragility — learned 2026-08-06 (Ranjith caught this):** the "how many r's in strawberry" tokenization demo now answers CORRECTLY and is retired. It became a famous benchmark (so it's in training data) and reasoning models spell the word out internally. General rule for any teaching session: **famous "watch the AI fail" demos get patched — a failure demo that succeeds is worse than no demo**, because the room concludes the limitation isn't real and stops trusting the presenter. Prefer demos that *show the mechanism* (tokenizer visualiser, empty-chat memory test) over demos that *catch a mistake*. Replacement for the token lesson: live tokenizer at platform.openai.com/tokenizer + Tamil-vs-English token count comparison (locally relevant — shows why Indian-language AI costs more). Same trap applies to the fake-citations hallucination demo: **web search must be OFF** or the model looks it up and the hook dies.

**AGENT DEFINITION CORRECTED (2026-08-07) — Ranjith pushed back twice, correctly.** The earlier "Study Buddy" (answer from notes, else Wikipedia) was NOT an agent — it was a tool-augmented chatbot, reactive, user-in-the-loop every turn. **Adding tools to a chatbot does not make it an agent.** The test to use: *does it do multi-step work toward a goal while you are not typing?* Ladder for teaching: chatbot → +RAG → +tools (still not an agent) → **agent (goal in, plans/acts/observes/re-plans, delivers)** → multi-agent. The loop is ReAct: GOAL → THINK → ACT → OBSERVE → **THINK AGAIN (this is the agent part)** → repeat → DELIVER.

**Revised build = "Unit Prep Agent"**: single instruction "Prepare me for Unit 3" → reads notes, identifies topics, *judges which are covered thinly* (real decision, not script), looks those up on Wikipedia, writes one row per topic to a Google Sheet with a practice question, reports back. Plus a **Schedule Trigger at 8pm** so it runs with the student absent. What makes it pass: goal-in-not-question, multi-step, each step depends on the last, acts on the world (sheet rows), runs without them. The money-shot demo is typing ONE instruction and watching 6 rows appear with nobody touching the keyboard. Key system-message lines that create agency: "Work through the entire goal before replying. Do NOT ask permission between steps." — delete those and it's a chatbot again.
