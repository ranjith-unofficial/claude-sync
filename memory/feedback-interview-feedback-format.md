When Ranjith writes up interview feedback that HR will read, default PM-lens crisp bullets (see [[feedback-communication-style]]) are not enough on their own — he explicitly flagged "HR won't be able to understand this" after a first draft.

**Why:** HR reads these to file a hiring decision, not to audit the reasoning like a PM would. Jargon-dense phrasing (e.g. "isolation of causal changes," "unprompted separation test") doesn't land with them.

**How to apply:** structure candidate interview feedback as two layers, both in one response:
1. **Summary** — recommendation + 4-6 plain-English bullets a non-PM can read cold, no jargon, no rubric-bucket names.
2. **Detailed** — the full area-by-area breakdown (rubric buckets, specific quotes/evidence, technical framing) below the summary, for his own record and for [[project-inc42-pt-interview-guide]]-style memory tracking.

Don't collapse to just one layer — HR needs the plain version, Ranjith needs the detailed version, and both belong in the same deliverable rather than making him ask twice.
